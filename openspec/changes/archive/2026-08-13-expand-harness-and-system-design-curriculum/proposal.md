## Why

The product already contains many of the ingredients for agent-harness engineering and classic system-design preparation, but they are fragmented across concepts, drills, and cases. Learners need a coherent harness-building progression and explicit practice coverage for the remaining high-value system-design archetypes so Learn, Blitz, Tradeoff, and Practice expose the same knowledge gaps.

## What Changes

- Add a searchable Harness Engineering roadmap that reuses existing agent-system concepts and introduces only the missing atomic ideas: harness architecture, repository instruction topology, environment/bootstrap contracts, durable work state, scope control, independent verification, run lifecycle, and harness evaluation.
- Add seven progressive harness projects, from a rules-first workspace through a complete maker-checker automation loop, with concept, drill, review, and synthesis links.
- Add thirteen structured system-design cases covering unique IDs, proximity search, nearby-presence, map routing, distributed queues, metrics ingestion, ad-click aggregation, hotel reservations, email delivery, object storage, gaming leaderboards, digital wallets, and stock exchanges.
- Map every new case to canonical learning concepts and drills, with quantitative anchors, failure injections, weighted rubrics, stronger answers, and authoritative sources.
- Add curriculum integrity checks that enforce the roadmap sequence, external coverage checklist, case inventory, and valid internal links without copying or embedding either external repository.
- Preserve every existing concept, roadmap, drill, case, attempt, and learning-state identifier.

## Capabilities

### New Capabilities

- `classic-system-design-gap-coverage`: Defines the thirteen additional interactive cases and their quality, remediation, compatibility, and discoverability contracts.

### Modified Capabilities

- `expanded-learning-domains`: Adds a coherent, project-backed Harness Engineering path inside Agent Systems while preserving stable curriculum identifiers and reusing existing concepts where they already provide the required coverage.

## Impact

- Canonical curriculum data in `src/data/` for concepts, drills, review questions, artifacts, roadmaps, and system-design cases.
- Learn and Practice discovery through existing roadmap and case selectors; no new top-level navigation or runtime dependency.
- Curriculum and case integrity tests, plus generated public curriculum artifacts where the existing pipeline derives them.
- Product documentation describing the new coverage boundary and attribution.
- No database migration, API shape change, authentication change, copied third-party content, production dependency, deployment, or release.
